= Git factory

Utilities for creating in-memory JGit repositories programmatically, primarily for use in tests. See link:CLAUDE.md[] for the architecture overview.

== `FastImporter`: fast-export format coverage

`FastImporter` parses `git fast-export` output into an `InMemoryRepository`. It is tested against blobs, multi-commit chains, nested/multi-level directories, executable files, symlinks, gitlinks, merge commits, multiple branches, annotated tags, distinct author/committer identities, the `encoding` header, non-ASCII content, and patch-style `M`/`D`/`R` operations (see `FastImporterTests` and the fixtures under `src/test/resources/…/*.fast-export`).

It does not cover the full `git fast-import` stream format. Known gaps, from most to least likely to matter in practice:

* *Quoted paths are not unescaped.* A real `git fast-export` quotes any path containing a space, e.g. `M 100644 :1 "old file.txt"`, `D "old file.txt"`. `MarkRegistry` never strips the surrounding quotes or interprets C-style escapes (`\"`, `\\`, `\n`, octal `\NNN`), so such a file lands in the tree literally named `"old file.txt"`, quote characters included. Verified by round-tripping actual `git fast-export` output through the importer.
* *`reset` is a no-op.* It never creates or updates a ref. Harmless for the common case (`reset refs/heads/main` immediately followed by `commit`, which is what all current fixtures use), but it means:
** Lightweight tags (`reset refs/tags/x` + `from :N`, no commit) cannot be imported — the dangling `from` line is silently dropped, with no error and no ref created.
** Branch deletion (`reset <ref>` + `from` all-zero SHA) is not supported.
* *`from`/`merge` only resolve mark references (`:N`)* — not branch names, raw/abbreviated SHA-1s, or `^0` expressions. Fine for streams built entirely within one import, but blocks referencing a parent that already exists in the target repository (incremental import).
* *Not supported at all:* `filemodify … inline` (git fast-export always uses a separate `blob` command instead), `notemodify`/git-notes, `alias`, `original-oid` (would break parsing if present, since `author` is currently read as mandatory rather than optional per spec), shorthand file modes (`644` vs `100644`), and the delimited `data <<EOF` form (only `data <length>` is supported, which is what `git fast-export` always emits).
* *Harmlessly ignored:* `checkpoint`, `progress`, `done`, `feature`, `option`, and stream comments (`#…`) — fine for this library's purpose of building a repository in one shot.
